Run

From the noe directory, with Odin on PATH:

./build.sh
./build.sh run
./build.sh release

./build.sh writes a debug build/noe.exe, copies lua54.dll beside it, and links a windowed subsystem (no extra console). ./build.sh run launches that build. odin run src keeps Odin’s console for print.

./build.sh release builds with -o:speed (no debug info) and writes build/noe-windows.zip containing only noe.exe and lua54.dll. That is the shipping pair. User config still comes from %APPDATA%\noe\ on the machine that runs it.

GitHub Release (pick a version):

git tag v0.1.0
git push origin v0.1.0
gh release create v0.1.0 build/noe-windows.zip --title "v0.1.0" --generate-notes

Config

User files live in %APPDATA%\noe\ (Roaming). The folder is created on first run. Missing files are silent — built-in defaults apply. Linux later: ~/.config/noe/.

  • init.lua — settings, binds, commands, hooks. Extra modules sit next to it; require("themes/amethyst") loads themes/amethyst.lua.
  • lex\*.lex — syntax highlighters, chosen by file extension. Unknown extensions fall back to odin.

project.noe is not AppData. It lives in the folder you open (or a parent): name, picker patterns, blacklist, commands, F-keys.

Reload without restart: Ctrl+Shift+R (reload_config). Save the Lua or .lex file first. Font size/path rebuild the atlas on that reload. Window size is still 1280×720 until a later setting exists.

What it is

  • Gap buffer + line index, UTF-8, IME
  • Immediate-mode layout: gutter, status, floating overlay (find, buffer switcher, file picker, new file)
  • Two horizontal panes, shared buffers, multi-cursor (Ctrl+D)
  • Status path from the project root, line count, and LF/CRLF
  • Undo groups that restore carets and selections
  • Lua 5.4: settings, binds, custom commands, hooks, status line

Not in yet

Vertical splits, regex find, tree-sitter, X11, Lua window size.
